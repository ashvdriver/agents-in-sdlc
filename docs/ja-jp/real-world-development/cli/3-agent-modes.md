最初は、プロジェクトに小さな機能を追加しました。しかし、より大きな変更には、より堅牢なプロセスが必要です。幸い、GitHub Copilot CLI は組織の既存のフローに合わせて動作するように作られており、適切なものを適切な方法で構築できます。このレッスンは、一般的なエージェント主導の開発プロセスに沿って進める一連のレッスンの最初のものです。Issue から新機能を生成し、コードが正しいこと、機能が期待どおりに動作することを確認して、最終的にプロジェクトへ問題なくマージします。

> [!NOTE]
> 機能のワークフローを進める間は、同じ会話とブランチを使い続けます。通常は、扱うファイルの種類ごとにブランチや PR を分けますが、ここでは中心的な概念に集中できるよう、手順を簡略化しています。

このレッスンでは、次の内容を学習します。

- GitHub Issue から新しい Copilot の会話を開始する。
- Plan モードで要件を定義する。
- Autopilot モードで新機能を実装する。
- コードをレビューする。
- 転送されたブラウザーで機能を手動で検証する。

この機能の作業を続ける中で、リポジトリの指示の更新、既存の `quality-checks` スキルのカスタマイズ、MCP による検証の追加、QA エージェントの作成、機能の PR の作成を行います。

## シナリオ

Tailspin Toys のカタログは拡大しており、訪問者はカテゴリーとパブリッシャーでゲームを絞り込む必要があります。バックログの Issue には機能が記載されていますが、カテゴリーの組み合わせ方などの詳細は、コーディングの前に合意しておく必要があります。Plan モードでそれらを決定してから、Autopilot で範囲を限定した実装を承認します。

## 背景

AI コーディングエージェントを開発フローに導入しても、基本は変わりません。むしろ、基本はこれまで以上に重要になります。多くの開発者は、次のようなフローで作業します。

1. 作業内容を説明した、登録済みの Issue から始める。
2. 構築する内容の計画を作成する。
3. コードを構築してレビューする。
4. テストを実行してコードを検証する。
5. 新機能を手動で検証する。
6. pull request (PR) を作成する。
7. コードがレビューされ、継続的インテグレーションが成功したら、コードをマージする。

> [!NOTE]
> 詳細はチームや組織によって異なりますが、ほとんどは上記のバリエーションです。

この標準的なアプローチに従うことで、AI が生成したコードが定められた要件を満たし、手作業で書いたコードと同じ審査プロセスを経ることを保証できます。

## 会話モード

**会話モード**は、エージェントにどこまで自律性を持たせるかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すと、モードを順に切り替えられます。

- **Interactive**: ユーザーとエージェントが協力して作業します。エージェントは変更を提案し、ユーザーの入力を待ってから先に進みます。
- **Plan**: エージェントが最初に計画を作成します。プロジェクトファイルは編集できません。
- **Autopilot**: エージェントが自律的に作業します。タスクが完了するまで、コードの記述、テストの実行、反復を行います。

まず Plan モードで始めて計画をレビューし、その後 Autopilot で実装します。

## Issue から開始する

フィルター機能の作業を始める前に、Codespace に戻り、リポジトリとターミナルの準備ができていることを確認します。

1. Codespace に戻ります。停止している場合は、再起動してから続行します。
2. 星評価の PR がマージされていることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新してから、フィルター機能の作業用ブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を2回押して、**Issues** タブを開きます。
7. <kbd>A</kbd> を押して、すべての Issue を表示します。
8. 矢印キーで、**Allow users to filter games by category and publisher** というタイトルの Issue を強調表示します。
9. <kbd>C</kbd> を押して、Issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトが `#7` (または近い番号) で始まっていることを確認してください。`#` を使うと、GitHub 上の Issue や pull request (PR) をコンテキストに取り込めます。

## フィルター機能を計画する

計画を立てると、機能の実装やタスクの実行を Copilot に任せる前に、取るべきアプローチを定義できます。複雑なものは、少し時間をかけて計画するのが常に有効です。Plan モードに切り替えて、Copilot に計画の作成を依頼しましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下のモード表示が **Plan** になっていることを確認します。
2. 前の手順で追加した Issue 参照の後ろに、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilot が計画の作成を開始します。まずプロジェクトを調査し、最適なアプローチを判断します。

3. 作業の途中で、Copilot からフィルター機能の動作について質問されることがあります。好みに応じて回答してください。正解や不正解はありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して計画を展開します。
5. 上下にスクロールして、計画をレビューします。
6. 決定した内容と合わない部分があれば、Copilot に計画の修正を依頼します。

## Autopilot を承認する

計画を作成してレビューしたら、実装に進みます。Autopilot を使って、Copilot に作業を任せましょう。Autopilot では、Copilot は完了したと判断するまで、課題に対して反復的に取り組みます。

1. **Accept plan and build on autopilot (recommended)**、またはインストールされているバージョンで同様のラベルが付いたオプションを選択します。
2. プロンプトの下のモード表示が **Autopilot** になっていることを確認します。
3. Copilot が確立された計画に沿って反復し、コードを生成してテストを実行する様子を見守ります。

> [!NOTE]
> 承認すると実装がすぐに始まる場合があるため、先に計画をレビューしてください。依存関係の不足やポートの競合が Copilot から報告された場合は、セットアップの問題を解決してから、チェックが完了したと見なしてください。

## 実装をレビューして検証する

コードが生成されたら、他のコードと同様に、マージ前にレビューする必要があります。コードをレビューし、サイトを実行して、すべて問題ないことを確認しましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに入ります。モード表示に **Plan** や **Autopilot** が表示されていないことを確認します。
2. `/diff` を入力し、フィルター機能の実装とテストを確認します。
3. 結果を Issue、および計画時に決定した内容と比較します。
4. コードのレビューが終わったら、<kbd>Esc</kbd> を押して差分表示を閉じます。
5. プロジェクトのチェックの出力をレビューし、失敗があれば解決するよう Copilot に依頼します。

## 新機能を確認する

コードに問題はなさそうですが、実際に動くでしょうか。以前と同様にアプリを起動し、Codespaces の転送ポート経由でサイトを開きましょう。

1. アプリを起動するよう Copilot に依頼します。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. ポート `4321` が利用可能になったと Codespaces が通知したら、**Open in Browser** を選択します。
3. カテゴリーによるフィルター、パブリッシャーによるフィルター、計画で合意した組み合わせを試します。
4. リセットの動作と結果が空の場合の動作が、Issue と決定した内容に一致することを確認します。
5. Codespace に戻り、起動した開発サーバーを停止するよう Copilot に依頼します。

## まとめと次のステップ

さまざまな会話モードを使って、機能を構築しレビューしました。このレッスンでは、次の作業を行いました。

- GitHub Issue から新しい Copilot の会話を開始した。
- Plan モードで要件を定義した。
- Autopilot モードで新機能を実装した。
- コードをレビューした。
- 転送されたブラウザーで機能を手動で検証した。
