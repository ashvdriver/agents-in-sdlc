GitHub Copilot をエージェントモードにすると、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。その作業は、ご自身のマシン上でリアルタイムに行われるため、VS Code の Copilot Chat では、すべてのツール呼び出しとファイルの編集が行われるたびに、その進行状況を確認できます。各差分をインラインでレビューし、個々の変更を承認または却下できます。さらに、エディターを離れることなく、追加のプロンプトで会話を方向付けて、作業を改善したり拡張したりできます。

この演習では、次の内容を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視する。
- 提案されたファイルの編集をレビューして承認する。
- セッションの途中でエージェントを方向付け、ハイコントラストと並べてライトモードのトグルを追加する。

## シナリオ

[演習 4][previous-lesson] で使用したアクセシビリティのカスタムエージェントが、ハイコントラストモードを実装しています。作業が進行している間に、デザインチームから追加の依頼がありました。デフォルトのテーマが暗すぎると感じるユーザー向けに、ライトモードのトグルも欲しいというものです。新しい会話を最初から始める代わりに、既存のセッションを方向付けて、作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各ステップ (調査するファイル、実行するコマンド、提案する編集) が表示されます。各ファイルの編集は、差分と **Keep** / **Undo** のコントロールとともに、チャット内にインラインで表示されます。

1. 演習 4 の Copilot Chat ビューに戻ります。
2. エージェントが作業する間、チャットをスクロールして、各ツール呼び出しが反映される様子を確認します。ファイルの読み取り、ファイルの編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
    - **Keep** を選択すると、変更を承認します。
    - **Undo** を選択すると、変更を元に戻し、エージェントにもう一度試させます。
4. チャットの上部にある **Files changed** インジケーターを開くと、このセッション中にエージェントが変更した作業セット全体を確認することもできます。

> [!NOTE]
> ツール呼び出しで権限が求められた場合 (たとえば、ターミナルコマンドの実行)、エージェントは一時停止して **Allow** プロンプトを表示します。問題ないと判断したコマンドのみを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。行った変更を要約した最終メッセージが表示されるはずです。

## ライトモードを追加するようエージェントを方向付ける

ハイコントラストモードが実装できたので、同じ会話を拡張して、ライトモードのトグルを追加します。同じチャットセッションを続けるため、エージェントは、変更したコンポーネント、使用したスタイリングのアプローチ、設定したローカルストレージのパターンなど、以前の作業のすべてのコンテキストを保持しています。

1. Copilot Chat の入力欄に、次の追加のプロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは中断したところから再開し、すでに行った変更を調べて、ライトモード用の追加を提案します。
3. ハイコントラストのときと同様に、各編集が反映されるたびにレビューします。各差分で **Keep** または **Undo** を使用します。
4. エージェントが望まない方向に進んだ場合 (たとえば、好ましくない方法でトグルの UI をリファクタリングしようとした場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、補足の追加メッセージを送信できます。

> [!TIP]
> 進行中のセッションを方向付けるほうが、最初からやり直すよりも速くなります。追加のプロンプトを使って、調整 (「CSS を簡素化して、セレクターを重複させずに CSS 変数を使用する」)、軌道修正 (「3つ目のトグルは追加せず、ライトモードを既存の設定パネルに統合する」)、範囲の拡大 (「両方のトグルにキーボードショートカットも追加する」) を依頼できます。

## 作業セットをレビューする

作業をコミットする前に、エージェントが変更したすべてのものを簡単に確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイルの一覧全体をレビューします。Astro コンポーネント、スタイル、関連するテストの更新が含まれているはずです。
3. 変更されたファイルをいくつか開き、差分を順に確認します。ARIA 属性、キーボードナビゲーション、セマンティック HTML、ローカルストレージによる永続化など、カスタムエージェントのアクセシビリティパターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。[次のレッスン][next-lesson]で公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視し、方向付けました。各ファイルの編集が反映されるたびにレビューし、変更を承認または却下して、コンテキストを失わずに作業を拡張するための追加のプロンプトを送信しました。

このレッスンでは、次の内容を確認しました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイルの編集を承認または却下する。
- 追加のプロンプトで、セッションの途中で方向付ける。

[次のレッスン][next-lesson]では、アクセシビリティの作業を pull request として公開し、このラボを通じてローカルのカスタムエージェントが生成した変更をレビューします。
